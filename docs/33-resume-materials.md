## 2. 核心亮点（简历 bullet points，按模块选 3-5 条）

### 2.1 邮件系统（最有深度，建议必选）

- 设计并实现**邮件全生命周期追踪系统**：9 态状态机（待发送→已提交→退信检测→重试）+ IMAP 退信轮询 + 永久/临时退信分类（RFC 3463）+ 退信黑名单，解决"SMTP 成功但用户未收到"的投递盲区问题【已实现】【已验证】
- 实现**父子重试模型**（record_type=ORIGINAL/RETRY + 唯一约束），保留完整发送历史链，支持管理端树形展示和人工重试【已实现】
- 采用**任务表模式**（先落库再发送），确保邮件记录不因发送过程崩溃而丢失【已实现】

### 2.2 支付与对账（业务价值高，建议必选）

- 设计**支付凭证审核系统**（方案B）：用户上传凭证截图 → OCR 初筛（Tess4j，自动识别金额/交易号）→ 水印+MD5/dHash 去重 → 管理员审核，解决第三方收款无法 API 回调的业务痛点【已实现】【已验证】
- 实现**多维度对账匹配引擎**：姓名(30)+手机(25)+金额(25)+时间(20) 评分模型，阈值≥60 自动匹配，低于阈值人工确认，不依赖第三方系统改造【已实现】
- 设计**OCR 优雅降级机制**：三级降级（初始化探测→运行时跳过→catch(Throwable) 兜底），解决 JNA 原生层抛 Error 导致凭证提交失败的 P1 故障【曾经发生】【已修复】

### 2.3 注册流程（体现全栈能力）

- 实现**9 步注册流程** + 中英双语国际化（vue-i18n，47KB+54KB 语言包）+ **两封邮件机制**（提交凭证即时通知 + 审核通过最终确认）【已实现】【已验证】
- 设计**三种支付确认路径殊途同归**：凭证审核通过/对账匹配确认/线下登记，均触发状态更新+通知邮件，简化原过度复杂的状态流转【曾经发生】【已修复】

### 2.4 系统架构（体现工程能力）

- 基于 youlai-boot 脚手架搭建**三端架构**：后端 API（Spring Boot 4）+ 管理端（基于有来框架 youlai-boot 二次开发，Vue3+TS）+ 门户端（Vue3+JS，**从零搭建**），37 张表，RBAC 权限（用户→角色→菜单→按钮级 perm）+ 数据权限【已实现】
- 集成 **Redisson+Caffeine 二级缓存**、**XXL-Job 定时任务**、**MinIO 文件存储**、**MapStruct 编译期对象映射**【已实现】

### 2.5 部署运维（体现独立交付能力）

## 3. 故障排查经历（面试讲故事的素材）

> 以下均为真实发生的故障，有完整排查过程。面试时按 STAR 法则讲述。

### 故事1: OCR JNA Error（最推荐，技术深度高）
- **S**: 用户上传支付凭证时系统报错，凭证提交功能完全不可用
- **T**: 定位并修复，恢复凭证提交
- **A**: 分析堆栈发现 `java.lang.Error: Invalid memory access`（非 Exception），追溯 Tess4j JNA 原生层异常不遵守 Java 异常体系，`catch(Exception)` 捕获不到 Error
- **R**: 改为 `catch(Throwable)` + `@PostConstruct` 前置探测 tessdata 路径 + available 标志三级降级，OCR 从"必须可用"变为"可选辅助"

### 故事2: 邮件中心数据库缺列（体现 Schema 管理意识）
- **S**: 管理端邮件中心页面报 `Unknown column 'record_type'`
- **T**: 恢复邮件中心功能
- **A**: 定位代码已升级父子重试模型但数据库未同步，对照 SQL 备份确认列定义
- **R**: ALTER TABLE 补 3 列+3 索引，DEFAULT 'ORIGINAL' 保证存量数据兼容；总结教训：实体字段变更必须同步 DDL

### 故事3: 审核通过未确认成功（体现业务流程理解）
- **S**: 凭证审核通过后用户状态仍为"审核中"，注册成功邮件未发送
- **T**: 让审核通过即注册成功
- **A**: 发现原设计有 review_passed 中间状态需对账确认，但协会不一定提供对账单，导致流程卡住
- **R**: 简化状态流转，审核通过直接设 paid+发邮件；统一三种确认方式殊途同归

### 故事4: SMTP 成功但邮件未送达（体现邮件链路认知）
- **S**: 邮件中心显示发送成功，但用户反馈未收到
- **T**: 建立投递失败感知能力
- **A**: 认知到 SMTP 250 只代表服务器接受，退信是异步到达的
- **R**: 设计 IMAP 退信检测+9态状态机+黑名单机制

## 7. 面试自我介绍模板（1分钟版）

> 我独立开发了一个国际学术会议管理系统 MCLC，这是三端架构——Spring Boot 4 后端、Vue3 管理端和门户端。后端和门户端是我从零开发的，管理端基于有来框架二次开发，从需求分析、编码到部署上线、域名备案都是我一个人完成的。
>
> 项目中最有挑战性的是两个问题：第一，协会收款无法提供支付回调，我设计了凭证上传+OCR初筛+人工审核的方案，配合多维度对账匹配引擎，纯靠双方已有信息交叉匹配；第二，邮件发送后无法感知投递结果，我设计了9态状态机+IMAP退信轮询+黑名单机制，能追踪每封邮件的完整生命周期。
>
> 开发过程中也踩过不少坑，比如 Tess4j 的 JNA 层抛 Error 而非 Exception 导致凭证提交失败，让我深入理解了 Java 异常体系和原生层交互的边界。上线后也独立处理过线上故障，比如邮件中心数据库缺列、论文审批502这些问题。
